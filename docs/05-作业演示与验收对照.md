## 4. 存档与恢复的实现要点（答辩会被问）

- **不依赖 `onDestroy`**：每次节点生效后立即「RDB 事务 → Preferences 快照 → 自动槽」，动画在落盘之后。进程被杀也丢不了。
- **两层存储分工**：Preferences 是加速层（小、同步快）；RDB 是事实层（可查询、可回放、可对账）。
- **恢复顺序**：自动存档槽（完整快照，能还原 JUDGE/ENDING 这类非节点事件）→ Preferences 快照（需 `seq` 与 RDB 一致）→ 事件流回放（兜底）→ 新局；恢复后 `sanitize()` 修正非法组合。
- **读档 = 整体替换**：清当前案的线索/flag/流水，再按快照重写，保证「读档即回到那一刻」。

## 5. 已知限制（如实说明）

1. **Hypium 用例的执行仍要在 DevEco 里点 Run**：`aa test` + 自建 runner 下 Hypium 不推进 spec（已实测并记录在 [04 检查单](04-首轮编译绿检查单.md)）。
2. **命令行构建需镜像到 ASCII 路径**：hvigor 拒绝中文工程路径，故提供 `tools/build-harmony.ps1`。
3. **无美术资源**：场景背景是纯色 + 文字，热点用列表而非坐标点击（数据结构里保留了归一化坐标，接美术时可直接换成图层命中）。
4. **音效**：未接入音频文件（设置项已预留）。
